## 2. 加密库: SpongyCastle

### 2.1 简介

SpongyCastle 是 BouncyCastle 加密库的 Android 移植版本。由于 Android 系统内置了精简版 BouncyCastle，直接使用会产生冲突，因此 SpongyCastle 通过重命名包名 (`org.spongycastle`) 来避免冲突。

### 2.2 使用场景

| 功能 | SpongyCastle 类 | 用途 |
|---|---|---|
| ECDH密钥协商 | ECKeyPairGenerator, ECDHBasicAgreement | 端到端加密握手 |
| SHA哈希 | SHA1Digest, SHA256Digest | 数据完整性校验 |
| AES加密 | AESEngine, CBCBlockCipher | 消息加密 |
| RSA签名 | RSAEngine | 数字签名 |
| Base64 | Base64 | 编码传输 |
| 随机数 | SecureRandom | 密钥生成 |

### 2.3 代码引用

在 `MusicPlaybackService` 中:
```java
import org.spongycastle.pqc.jcajce.spec.McElieceCCA2KeyGenParameterSpec;
// 使用 SHA1 进行缓存文件命名
MessageDigest.getInstance(McElieceCCA2KeyGenParameterSpec.SHA1)
```

在 `MainActivity` 中:
```java
import org.spongycastle.i18n.MessageBundle;
// 用于通知标题字段名
```

## 3. ECDH 密钥协商

### 3.1 协议概述

ECDH (Elliptic Curve Diffie-Hellman) 是一种基于椭圆曲线的密钥协商协议，允许双方在不安全的通道上协商出共享密钥。

### 3.2 在 OldChat 中的应用

推测 OldChat 使用 ECDH 实现端到端加密 (E2EE):

```
用户A                           用户B
  │                               │
  │ 生成密钥对 (a, A=aG)          │ 生成密钥对 (b, B=bG)
  │                               │
  │ ──── 发送公钥 A ────────────→ │
  │ ←──── 发送公钥 B ──────────── │
  │                               │
  │ 计算共享密钥:                  │ 计算共享密钥:
  │ S = aB = abG                  │ S = bA = abG
  │                               │
  │ ──── S 相同，握手完成 ────    │
```

### 3.3 相关类

- `o0.AbstractC0437d` — 认证初始化，可能包含密钥协商
- `o0.AbstractC0435c` — 后台任务，可能包含密钥轮换
- ECDH 相关类在混淆后的包中，具体类名未知

## 4. 认证机制

### 4.1 Token 认证流程

```
1. 用户登录
   POST /auth/login {identifier, password, device_id, ...}
   ↓
2. 服务端返回
   {access_token, refresh_token, user: {id, uid}}
   ↓
3. 客户端存储
   SharedPreferences("auth").putString("access_token", token)
   ↓
4. API请求携带
   Authorization: Bearer <access_token>
   ↓
5. Token过期
   使用 refresh_token 获取新的 access_token
```

### 4.2 Token 存储

| 键 | 值 | 风险 |
|---|---|---|
| access_token | JWT Token (明文) | 中 |
| refresh_token | Refresh Token (明文) | 中 |

### 4.3 登录安全

登录请求体:
```json
{
    "identifier": "用户名",
    "password": "密码",          // 明文传输 (依赖HTTPS)
    "device_id": "设备唯一ID",
    "imei": "IMEI号",
    "device_name": "设备型号",
    "platform": "android",
    "app_version": "1.3.61"
}
```

**风险**: `usesCleartextTraffic=true` 允许 HTTP 明文传输，密码和Token可能被截获。

### 4.4 设备绑定

登录时携带设备信息 (device_id, imei, device_name)，服务端可进行设备绑定和异常检测。

## 6. 安全风险清单

### 6.1 高风险

| 风险 | 说明 | 影响 |
|---|---|---|
| **明文密码存储** | `saved_password` 以明文存储在 SharedPreferences | 设备被Root或备份后密码泄露 |
| **明文HTTP流量** | `usesCleartextTraffic=true` | 中间人攻击可截获Token和密码 |
| **allowBackup=true** | 应用数据可通过ADB备份 | 攻击者可提取所有本地数据 |

### 6.2 中风险

| 风险 | 说明 | 影响 |
|---|---|---|
| Token明文存储 | access_token 未加密 | 设备被Root后Token泄露 |
| IMEI收集 | 登录时发送IMEI | 隐私问题 |
| 无证书固定 | 未发现Certificate Pinning | 中间人攻击可能性 |
| READ_PHONE_STATE | 可获取设备标识 | 隐私问题 |

### 6.3 低风险

| 风险 | 说明 |
|---|---|
| 用户名明文存储 | saved_username 明文 |
| minSdkVersion=9 | 支持极老设备，安全特性受限 |

## 7. 安全建议

### 7.1 存储安全

```
当前: SharedPreferences (明文)
建议: EncryptedSharedPreferences (AndroidX Security)
     或 Android Keystore + 加密存储
```

### 7.2 传输安全

```
当前: usesCleartextTraffic=true
建议: 设置为 false，强制HTTPS
     添加 Network Security Config
     实施 Certificate Pinning
```

### 7.3 备份安全

```
当前: allowBackup=true
建议: 设置为 false
     或使用 android:fullBackupContent 排除敏感文件
```

### 7.4 密码安全

```
当前: 明文存储密码
建议: 不存储密码，仅存储Token
     Token过期后要求重新登录
```

```java
if (errorCode == 403 || response.contains("user_banned") || response.contains("device_banned")) {
```
