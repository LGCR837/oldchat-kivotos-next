# 2026-08-12 工作日志

## 频道头像 401 根因与修复（关键！）
- **现象**：`/channel-media/ca-XXX.jpg` 无论 v1 Bearer / v2 签名 / 无鉴权 都 401，控制台刷 ~300 条。
- **真正根因**：`resolveMediaUrl` 把 `channel-private:ca-XXX.jpg` 映射成 `http://oc.mcl0.dpdns.org/channel-media/ca-XXX.jpg` 形态本身**正确**（文档 §14.10：`GET /channel-media/{filename}` 是「全局签名下载」，签名在文件名里）。问题在 `shouldCache()` 对 `http://oc.mcl0/channel-media/...` 返回 true → 频道头像被 `MediaCache` 接管，经 `fetchOne` 带了 `Authorization: Bearer`（及 v2 签名头）去抓**签名 URL** → 服务端对带鉴权头的签名 URL 直接拒签返回 401。且 MediaCache 的异步多阶段管线（memCache 未命中→IDB 查找→fetchAndStore→fetchOne→tauriHttpFetch/reqwest 往返 + 重试循环）把请求推到签名 TTL 之后 → 一旦过期永远重试 → 刷屏。
- **修法**：`shouldCache()` 对 `/channel-media/` 与 `channel-private:` 返回 false。`MediaCache` 不再接管频道媒体 → `<img>` 保留解析后的签名 URL，由**浏览器原生发无鉴权 GET**（与官方 Android 客户端 ImageView 一致）。`channelCard` 自带 `onerror="this.src='assets/default-avatar.png'"` 优雅回落。
- **效果**：消除 401 刷屏；签名在 TTL 内（发现页实时 discover 返回的签名新鲜）即出图；过期则回落默认头像而非裂图/刷屏。
- **副作用**：`fetchOne` 里的 `signV2ForAnyPath` 频道媒体分支变为死代码（不再被调用），保留无害。
- **验证**：`node --check src/app.js` 通过。前端改动热重载即可，无需重编 Rust。用户需 `npm run tauri dev` 重启看发现页频道头像。
- **残余风险**：侧边栏「我的频道」用 localStorage `oc_subscribed_channels` 缓存的 `avatar_url`（跨设备订阅同步时写入），若该缓存签名已过期 → 回落默认头像（不再刷屏，但可能不出图）。根治需订阅列表也走实时元数据刷新（待做）。

## 关键结论（频道媒体鉴权模型）
- 频道**头像/封面/频道媒体** = `channel-private:ca-XXX[.ext]` → `/channel-media/ca-XXX[.ext]`，**全局签名下载、URL 即凭证、严禁带 Authorization 头**，必须用原生 `<img>` 加载。
- 频道**帖子里的文件媒体** = `https://files.mcl0.dpdns.org/v2/files/download/xxx`（文档 §14.7 示例），走 `/v2/files/download/{id}`，仅 Bearer 鉴权（§4.5），可走 MediaCache。
- 两者不要混：之前把频道媒体错当 `/v2/files/download` 是 404 源头；后来改 `/channel-media/` 路径对了但被 MediaCache 带鉴权头搞 401。
