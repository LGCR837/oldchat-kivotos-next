## 新增启动期环境自检 preflight（Windows + Linux）—— 已完成
新建 `src-tauri/src/preflight.rs`（~570 行），在 `run()` 里先于 `tauri::Builder` 执行。

核心决策：**不能用 tauri-plugin-dialog**（它依赖 WebView2/GTK，而要报的恰恰是这些缺失），
改用 Win32 `MessageBoxW`（+ `ShellExecuteW` 打开下载页）和 Linux 的 zenity→kdialog→xmessage→stderr 降级链。

分级：Fatal 弹窗+引导+exit(1)；Warn 写 stderr + 缓存，经 `env_report` 命令交前端「设置→关于」页展示。

检测项：Win 的 WebView2（webview_version() + 注册表 pv 三处双保险）/ 系统 build（<10240 阻断，<17763 提醒）；
Linux 的 DISPLAY|WAYLAND_DISPLAY、WebKitGTK so 扫描（按 /etc/os-release 给 apt/dnf/pacman/zypper 对应命令）、
AppIndicator（Warn，文案必须说明「本程序关闭=隐藏托盘，托盘没了窗口找不回来」）；通用的数据目录可写探测。

**两个误报陷阱（务必保留）**：
1. `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 非空必须直接豁免 —— 企业固定版本部署既不写注册表也不响应运行时探测。
2. Linux so 检测覆盖面有限：WebKitGTK 缺失通常在动态链接阶段就挂，到不了 main，属尽力而为。

附带：检测到 NVIDIA 驱动自动设 `WEBKIT_DISABLE_DMABUF_RENDERER=1` 规避白屏（仅在用户未显式设置时）；
`Builder::run()` 返回 Err 时调 `report_runtime_failure()` 兜底弹窗（release 无控制台，否则用户只看到「闪一下就没了」）。

自测入口：`OLDCHAT_PREFLIGHT_DEMO=webview2|webkit|display|runtime` 强制预览弹窗后退出。

其他改动：Cargo.toml windows-sys 补 `Win32_System_Registry` + `Win32_UI_Shell`；lib.rs 新增 `env_report` 命令；
app.js 关于页加「系统环境」「WebView」两行 + 环境提醒区（异步 invoke env_report）；dev1.md 新增 4.7 章节。

验证：cargo check/build 零警告；实测 webview2 与 runtime 两种弹窗均正常阻塞，
PowerShell 读到窗口标题「缺少 Microsoft Edge WebView2 运行时」中文无乱码；

## v1.4.x 逆向文档更新 → 适配分析（交付 docs/v1.4.x-adaptation-plan.md）
用户全面更新了 nx/ 逆向文档至 v1.4.x（原为 v1.3.61），新增 oldchat-diff-v1.3.61-vs-v1.4.x.md。
方法：读 diff + 02/03/05/08 文档，逐条与 app.js 实际实现（端点清单、字段用法、capabilities）对照。

**结论：不是协议破坏性升级。** 三类：

P0 必改（2 项）：
1. 媒体迁移阿里云 OSS（`ocf.oss-cn-shanghai.aliyuncs.com`）。capabilities 白名单只有 `https://**`
   兜住了 https 版，**http 版无匹配 → plugin-http 静默拒绝**，表现为图片/语音加载失败且报错不直观。
   还有一处易漏：媒体缓存 `mediasOriginSet`（L477）只收 MEDIA_ORIGIN+BACKEND_ORIGIN，
   OSS 资源不进 IndexedDB → 不报错但每次重新走网络。
2. NCUID 写入侧内部不一致：读历史已用 `?with_ncuid=`（L4319/4520），但 `toUidParam()`/`withUidParam()`
   （L1262-1269）仍固定发 `to_uid`/`with_uid`。建议按官方「双写双读」改成两字段都发。
   注意 mentions 我们 L5633 已同时写 uid+ncuid，是最稳形态，**别按文档改成只发 ncuid**。

P1 缺口（5 项）：消息搜索（`/direct|groups/messages/search` —— gap-analysis 里「全局搜索做不了」的
判断因此失效）、群增量同步 `/groups/messages/after`（可修复 WS 重连消息空洞隐患）、
音乐歌词/详情/播放列表/点赞评论、表情广场搜索、分页参数对齐（plaza 30 / ranking 50，我们都是 20）。

P2 无需动（4 项）：
- **Conscrypt TLS 对我们零影响** —— 它替换的是 Android 系统 TLS，我们走 plugin-http，
  且后端是 HTTP 明文。diff 标其「影响级别：高」极易误导，已在文档中明确记录避免后人折腾。
- ECDH 协议未变（08 文档 diff 仅改标题+加 Conscrypt 描述，握手/信封 `{iv,data,mac}` 一致）。
- RegisterActivity 移除是 Android 侧，我们用 `/v1/auth/web/register`，大概率无影响但需回归测试。
- B站模块重构（Wbi 签名+40模型）只是把本就缺失的缺口门槛抬高，维持暂不实现。

**文档自身有矛盾，落地前必须实测**：03 §2.4 说历史查询「仍建议 with_uid」，§11.1 示例却是
`with_ncuid`，§2.2 又标「待验证」——我们线上用 with_ncuid 正常，说明 §2.4 已过时。
mentions 字段名 §4.2（uid）与 §4.3（ncuid）也打架。双写方案的价值正是绕开这些不确定性。
