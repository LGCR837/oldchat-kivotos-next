## 发行矩阵扩展 + 下载页改造（未 commit）
- **需求**：①CI 增加 Linux amd64 的 AppImage/deb/rpm、Windows 内嵌 WebView2 安装包、macOS dmg；②下载页不限制一行个数，且新格式对 v4~v9 不生效。

### 1) Tauri 配置（src-tauri/tauri.conf.json）
- `bundle.windows.webviewInstallMode: "EmbedBootstrapper"`（NSIS 内嵌 WebView2 引导，普通用户无需手动装框架）；`bundle.macOS.minimumSystemVersion: "10.15"`。

### 2) CI（.github/workflows/release.yml）新增 3 个 job
- `linux-bundles`：ubuntu-22.04 + amd64，apt 加装 `libfuse2 appstream`，`--bundles appimage,deb,rpm`（不加 `--no-bundle`、不设 uploadPlainBinary → 只传包）。保留原 linux 任务的免安装单文件。
- `windows-installer`：amd64+arm64，`--bundles nsis`（内嵌 WebView2），保留原 windows 任务的免安装 .exe。
- `macos`：aarch64+x86_64，`--bundles dmg`（**未签名**；用户确认先出未签名 dmg，附"右键→打开 / xattr -cr"放行说明，后续有 Apple 证书再补 notarize）。
- 三 job 的 `if` 与原 windows/linux 任务一致（release 触发 / workflow_dispatch 的 linux_only / build_all）。
- YAML 经人工核对缩进；本机无 pyyaml，未做机器校验。

### 3) 下载页改为「按真实资产动态渲染」（关键设计）
- **根因**：原 `functions/download.js` 的 `buildAssets(tag)` 与 `public/script.js` 的 `TARGETS` 都是**写死的 5 产物**，`assetUrl` 按 `oldchat-kivotos-next-app-{tag}-{suffix}` 拼名。新包（AppImage/deb/rpm/NSIS/dmg）命名是 Tauri 默认格式（含空格/不同后缀），写死拼名会对不上。
- **做法**：`functions/api/refresh.js` 现在把每个 release 的 `assets:[{name,browser_download_url,size}]` 也写进 KV。`download.js`/`script.js` 新增 `classify(name)`（按后缀+arch 正则归类 OS/架构/格式）+ `RANK`（排序）+ `buildLinksFromAssets(assets)`（按真实 `browser_download_url` + MIRROR 前缀渲染，未知后缀跳过）。**无 assets 时回退** `buildAssets`/`TARGETS`。
- **「对 v4~v9 不生效」自动满足**：v4~v9 的 GitHub Release 只有旧 5 产物，真实资产里根本没有 AppImage/deb/rpm/NSIS/dmg，自然不显示；新格式从下一个 Release（v10+）起出现。无需版本号硬编码判断。
- `functions/download.js` 的 `.dls` 网格 `repeat(3,…)` → `repeat(auto-fill,minmax(160px,1fr))`（去除一行个数上限）；`public/script.js` 的 `.dl-links` 本就是 `flex-wrap` 无需改 CSS。两处文案更新（提及 AppImage/deb/rpm/NSIS/macOS，以及 macOS 未签名放行说明）。
